# 7 — Scaffold a Module

**What you'll do:** Use the Velora CLI to generate a complete CRUD module — service, repository, data source, controller, and pages — then understand what was generated and how to extend it.

---

## Start a new app

Create a brand new Velora-powered Flutter app:

```sh
dart run velora_cli new my_app
```

Pass `--platforms=android,windows` to run `flutter create` for those platforms in the generated directory. Without it, the command writes the app skeleton only. The skeleton has constructor-injected splash/auth/dashboard modules, a `GetMaterialApp` wired to a hand-written `AppRouter.onGenerateRoute` switch, a theme file, `.ai/` context files, and an `AGENTS.md` with the managed lookup section described in [Agent Tooling](agent-tooling.md). The generated `pubspec.yaml` lists `velora_cli` under `dev_dependencies`.

Use `velora list` or `velora --help` to list commands, and `velora new --help` (or `-h`) for command usage.

## Scaffold auth

Add the login screen and auth flow:

```sh
dart run velora_cli make:auth --sanctum
```

Generates `lib/app/modules/auth/` with a login page and an auth controller.

## Scaffold a theme

```sh
dart run velora_cli make:theme --preset meadow --font "Inter"
```

Writes `lib/resources/theme/app_theme.dart` with light and dark themes from
`velora_ui`. Add `velora_ui` to your app's dependencies. The preset defaults to
`aurora`; `meadow`, `neutral`, and `corporate` are also available. The font is
optional and must be available to the app. Pass `--force` to replace an existing
theme file.

## Scaffold a CRUD module

Generate a complete feature module for any resource:

```sh
dart run velora_cli make:module users --crud
```

Writes `lib/app/modules/users/` containing:

```
users/
  users_module.dart                    ← factory: wires dataSource → repository → service → controller
  users_routes.dart                    ← route name constants for this module
  models/
    users_model.dart
  data/
    users_remote_data_source.dart      ← calls Velora.api
    users_repository.dart              ← implements VeloraRepository<UsersModel, int>
  services/
    users_service.dart                 ← plain class, not GetxService
  controllers/
    users_controller.dart              ← extends VeloraController
  pages/
    users_index_page.dart
    users_show_page.dart               ← --crud only
    users_create_page.dart             ← --crud only
    users_edit_page.dart               ← --crud only
```

It also writes `test/modules/users/users_controller_test.dart` with a starter
controller test. If `.ai/module-map.json` exists, the CLI adds the module's
name and index route while preserving existing entries.

There is no `bindings/` directory and no `Bindings` subclass: `${ClassName}Module` is a plain class with a static `controller()` factory method that constructs the data source, repository, service, and controller by hand with constructor injection — the same pattern `velora new` uses for its generated modules. `data/` is flat (no `sources/`/`repositories/` split) and there is no generated mock data source; swap implementations by changing what `${ClassName}Module.controller()` constructs. Services are plain classes, not `GetxService`.

`users_routes.dart` only declares this module's route name constants (plus `show`/`create`/`edit` helpers for `--crud`) — it is **not** wired into a global route table for you. The app generated by `velora new` uses a hand-written `switch` in `AppRouter.onGenerateRoute` (see [Architecture](architecture.md)), so add the new routes and pages there yourself.

## Run a health check

```sh
dart run velora_cli doctor
```

Read-only checks against the current directory: `pubspec.yaml` exists and depends on `velora`; `lib/main.dart` exists and calls `Velora.boot(...)`; any installable plugin package (see `velora install`, below) that's already a pubspec dependency but isn't actually wired into `Velora.boot(plugins: [...])`; and the detected Dart/Flutter versions against the required baseline (Dart >=3.13.0, Flutter >=3.47.0 — see [Toolchain baseline](toolchain.md)). A missing/misconfigured `velora` dependency is a hard failure (nonzero exit); everything else — missing `main.dart`, a missing `Velora.boot()` call, an unwired plugin, a Flutter or Dart SDK that is missing or below the baseline — is reported as a warning and still exits `0`.

## Install a plugin package

```sh
dart run velora_cli install velora_offline
```

Adds the package to `pubspec.yaml`, wires its plugin into `Velora.boot(plugins: [...])` in `lib/main.dart`, and runs `pub get` — the Laravel-style "install and it's wired for you" step. Pass `--no-wire` to skip editing `main.dart` or `--no-pub-get` to skip fetching dependencies.

When `velora` uses a path or Git dependency, the installed package uses the same source and a sibling package path; hosted dependencies use the catalog's version constraint.

## Scaffold database files

`velora make:migration create_users` writes `lib/database/migrations/create_users_migration.dart`. Set its version to a unique schema version and add the SQL changes. `velora make:repository users` writes `lib/app/data/users_repository.dart` for app-specific data access. Existing files are not overwritten.

## All CLI commands

| Command | What it does |
|---|---|
| `velora_cli new <name>` | Create a new app skeleton |
| `velora_cli make:auth --sanctum` | Scaffold login + auth flow |
| `velora_cli make:theme [--preset <preset>] [--font <family>] [--force]` | Generate light and dark themes from a preset |
| `velora_cli make:module <name> --crud` | Generate a full CRUD module |
| `velora_cli make:module <name> --form` | Add a form page, validation controller, and controller test; can be combined with `--crud` |
| `velora_cli make:notifications` | Generate notification center module |
| `velora_cli install:push --fcm` | Add FCM push setup files |
| `velora_cli install:push --local` | Add local notifications setup files |
| `velora_cli install <package>` | Install a Velora plugin package: add the dependency, wire it into `Velora.boot()`, and run `pub get` |
| `velora_cli doctor` | Check the `velora` dependency, `Velora.boot()` wiring, unwired installed plugins, and the Flutter/Dart versions against the required baseline |

See [CLI Commands →](commands.md) for the full reference including package-level `flutter analyze` and `flutter test` commands.
